# 독립 질문의 긴 대화와 문맥 예산

이 문서는 상위 프로젝트가 **2026-09-11에 작성한 수정 설명과 검증 이력**의 한국어판입니다. [원문](../docs/upstream/sidequestion-CONTEXT_BUDGET.md)을 보존하며, 아래의 과거 통과·서버 재시작 기록을 이번 한국어 문서화의 테스트 결과로 주장하지 않습니다.

기존 구현은 요청 JSON의 문자 수를 곧바로 토큰으로 보고 주 작업의 32K 출력 예약분을 상속했습니다. 따라서 HTML·JS·도구 결과가 많으면 모델에 넣을 수 있는 질문도 일찍 거부했습니다.

## 2. 요청 예산과 실제 실행 순서

1. **내용 기반 입력 추정.** Norma의 UTF-8 바이트 기반 블록 추정에 4/3 여유를 적용하고 system, tool schema, 메시지 봉투 비용을 더합니다. 공급자의 정밀 토큰 수가 아니라 보수적 추정입니다. JSON 직렬화 중 HTML escape가 증가한 길이를 그대로 토큰 수로 사용하지 않습니다.
2. **독립 출력 예약.** 기본 최대 8192 토큰이며 주 설정의 출력 상한이 있으면 그보다 커지지 않습니다. 서버 환경 변수 `ARTEX_BTW_MAX_OUTPUT_TOKENS`로 256–32768 범위의 상한을 정할 수 있습니다. 제품 기본 모델이나 주 작업의 매개변수를 변경하지 않습니다.
3. **입력 창 확보.** 입력 예산은 문맥 창 − 출력 상한 − 안전 여유입니다. 창 미지정은 200K로 취급합니다. 여유는 창의 5%, 최소 128·최대 8192 토큰입니다.
4. **최근 문답 제한.** 성공 문답을 증가하는 ordinal 순으로 페이지당 최대 20개씩 읽습니다. 원문은 최대 20쌍을 유지하며 예산은 입력의 1/4 및 16K 이하입니다.
5. **오래된 이력 요약.** 넘치는 문답을 롤링 요약에 합칩니다. 출처와 스냅샷 시각을 남기며 과거 어시스턴트 답변을 새로운 도구 증거로 보지 않습니다. 충돌하면 최신 주 스냅샷을 우선합니다.
6. **주 문맥 복사본 압축.** 아직 길면 오래된 메시지만 요약하고 최근 최대 8K 토큰을 유지합니다. 도구 호출/결과의 경계를 끊지 않으며 단일 묶음이 너무 커도 통째로 요약합니다.
7. **요약 요청도 예산 제한.** 실제 남은 창에 맞춰 UTF-8 안전 분할합니다. 요약 출력 상한은 2048입니다. 빈 응답, 잘림, tool use, 예산을 넘는 요약은 캐시에 저장하지 않습니다. 질문당 요약 호출 최대 12회와 같은 120초 마감을 적용합니다.
8. **초과 복구 한 번.** 첫 답변 요청이 문맥 초과로 실패했고 텍스트/tool use가 없을 때만 더 줄여 재시도합니다. 추정 크기가 줄지 않았으면 중단합니다. 다른 오류와 이미 일부 출력된 스트림에는 이 복구를 적용하지 않습니다.
9. **사용량 합산.** 요약, 실패 시도, 취소 전 받은 usage를 같은 독립 질문에 합칩니다. Provider가 사용량을 반환하지 않으면 실제 수치는 0으로만 남을 수 있으며 입력 추정을 실측 사용량인 것처럼 저장하지 않습니다.

구현 함수는 [request.go](request.go)의 `EstimateInputTokens/outputBudget/inputBudget`, [context.go](context.go)의 `loadHistory/foldHistory/messageGroups/compactSnapshot/prepare/Respond` 순서로 읽으면 됩니다.

## 3. 저장과 화면

`side_question_sessions.memory`는 과거 문답 요약, 요약한 ordinal, 스냅샷 신원별 주 문맥 요약 캐시를 저장합니다. `side_question_requests.context_info`에는 준비 단계, 실제 재생 문답 수, 요약 사용 여부, 예산 추정을 보존합니다.

요약은 원래 요청이 아직 실행 중이고 정리 세대가 같을 때만 저장합니다. 이력 삭제는 요약 캐시도 지워 늦은 쓰기가 지운 데이터를 복구하지 못하게 합니다. 새 스냅샷은 옛 스냅샷 요약을 재사용하지 않습니다. 요약 필드는 v3 작업 아카이브에 포함하며, 해당 필드가 없는 예전 v3는 빈 객체로 복원하고 v1/v2도 계속 지원합니다.

POST는 요청을 먼저 수락·반환하고 준비/압축을 백그라운드에서 수행합니다. 압축 동안 수락 잠금이나 DB 트랜잭션을 잡지 않습니다. SSE와 이력은 준비, 문답 정리, 복사본 압축, 답변 생성 단계를 표시합니다. 압축 실패는 해당 독립 질문의 실패 종료 상태로 저장합니다. 프런트엔드는 오류를 남기고 실패한 질문 초안을 복원하며, 이력 polling이 제출 오류를 지우지 않게 합니다.
