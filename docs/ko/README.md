## 코드 주석의 읽는 방법

각 소스 파일의 한국어 해설은 그 파일이 맡은 경계를 먼저 설명합니다. 큰 파일에는 주요
함수와 상태 변화 주변에도 주석을 넣었습니다. 원래의 중국어·영어 주석과 함께 읽을 수 있고,
오래된 원문 설명이 현재 코드와 다르면 한국어 해설이 현재 구현과의 차이를 짚습니다.

주석이 함수의 모든 문장을 반복하지는 않습니다. 함수의 입력, 상태를 바꾸는 지점,
결과가 저장되는 위치, 다른 파일로 넘어가는 호출을 중심으로 읽으세요. 작은 문법보다
“이 값은 누가 만들고 누가 소비하는가”를 따라가면 전체 코드가 연결됩니다.

실행 프롬프트와 도구 description 문자열은 모델의 행동을 바꾸는 입력이므로 원문을
유지합니다. `skills/`의 문서도 에이전트가 읽는 실행 지시입니다. 사람을 위한 한국어
해설은 [Skill 가이드](skills.md)와 연결된 번역/해설 문서에서 제공합니다.

## 반드시 구분할 개념

| 개념 | 의미 | 혼동하면 안 되는 점 |
| --- | --- | --- |
| `task` | 사용자가 만든 작업 | 작업마다 새 모델을 학습하지 않음 |
| `exploration` | 작업의 탐색 기록 묶음 | 자산의 전역 저장소와 별개 |
| `goal` | 최종적으로 달성하려는 상태 | 바로 실행하는 명령 목록과 다름 |
| `intent` | Worker 하나가 수령하는 실행 방향 | 동일한 의도의 의미 중복까지 자동 제거되는 것은 아님 |
| `fact` | 도구 관찰 또는 추론을 기록한 노드 | 독립 검증된 절대적 사실이라는 뜻이 아님 |
| `finding` | 발견을 나타내는 그래프 노드와 별도 DB 레코드 | 두 ID가 다르므로 API별로 확인해야 함 |
| `anchor` | 탐색 노드와 자산의 연결 | 자산 자체가 탐색 노드가 되는 것은 아님 |
| `digest` | 비활성 원본 노드 묶음의 요약 | 원본 삭제나 모델 파라미터 학습이 아님 |
| `transcript` | 모델·도구 대화 이력 | 영속 실행 기록과 현재 모델 입력량은 다름 |
| `activity` | 화면/조회용 실행 이벤트 | SSE 자체가 유일한 원본 저장소는 아님 |
| `judge` | 선택적 도구 승인 판단 모델 | 발견의 진실성을 항상 검증하는 역할이 아님 |
| `retester` | 수동으로 요청한 발견 재검증 | 매 발견마다 자동 실행되는 기본 단계가 아님 |

## 입문용 추적 연습

1. `server/goals.go`에서 사용자 요청이 어떻게 작업과 목표가 되는지 찾습니다.
2. `server/engine.go`의 `Run`, `plannerLoop`, `workerLoop`, `claimNext`를 읽습니다.
3. `db/exploration.go`의 `ClaimIntent`에서 `state='open'` 조건을 확인합니다.
4. `agent/worker.go`에서 수령한 의도가 세션 입력으로 바뀌는 과정을 읽습니다.
5. `agent/tools.go`와 관련 `tools_*.go`에서 사실·발견을 기록하는 도구를 찾습니다.
6. `server/server.go`의 SSE 핸들러와 프런트 `web/src/lib/api.ts`를 연결해 이벤트가 화면에 나타나는
   경로를 확인합니다. 정확한 파일별 설명은 서버/프런트 가이드를 함께 보세요.
7. 같은 기능의 `_test.go`를 읽어 성공 사례뿐 아니라 실패·중단·동시성 조건을 확인합니다.

## 문서의 근거와 현재 범위

이 문서들은 고정한 원본 소스를 직접 읽은 해설입니다. 코드 경로 링크가 근거이며,
설계 제안은 [개선·응용](improvements.md)에서 현재 구현과 분리했습니다.
과거 변경 기록의 “수정 완료” 문장은 그 버전의 기록입니다. 오늘의 모든 상황에 대한
실행 보증으로 확대하지 않습니다. 실제 검증은 [검증 기록](validation.md)을 확인하세요.
